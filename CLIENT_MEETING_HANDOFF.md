## Gotchas learned this round
- Two independent field-rule tracks: per-role (`grantor_/recipient_/volunteer_`, used by the
  app's registration) and the dashboard New-User form's own `user_` track (migration 057).
- `rulesFor(roleId)` omits ungoverned columns; `isCollectedForRole` reads "absent" as hidden.
- `.top-action-bar` layout is tuned around a fixed set of children — don't unmount bar
  buttons conditionally; use `visibility:hidden`.
- `/api/admin/users` per_page > 100 silently becomes 20 (not 100). Never ask for a big page to
  "get everyone" — use `lib/fetchAllUsers.ts` (or a server-side filter).
- Test DB gotcha: seeding users with explicit high ids (9101…) leaves the id sequence behind, so
  tests' new rows get LOWER ids and fall off "newest first" pages → false failures. Use a clean DB.
- notify.Send dedupes (user,title,body,type,related_entity_id) for 2 min and IGNORES related_entity_type — ids from different tables collide; exempt real state-change types via chatNotificationTypes.
- Global CSS sets `button { height: 36px }` — any multi-line custom button (list rows) needs
  `height: 'auto'` (+ `alignItems: 'stretch'` for a column flex).
- `uq_chat_pair` (migration 012) was the real one-thread-per-pair rule, not just the lookup;
  migration 135 swaps it for a per-section index.
- Delete routes pass `RequireDeletePassword` (group-level) before per-route guards — test guards
  on DELETE with a password body.
- Page toolbar controls belong in `<PageActions>` (or inside `<PageHead>` in the same
  component), never as plain page-body rows.
